## Phase 1 — Semantic Search Engine

### Block 1A — Local pipeline proof of concept ✅

**What was built:**
- `app/pipeline/clip.py` — CLIP ViT-B/32 image and text embedding
- `app/pipeline/yolo.py` — YOLO11n object detection and tagging
- `app/pipeline/blip.py` — BLIP-2 OPT-2.7B natural language captioning
- `scripts/run_pipeline.py` — single-image pipeline entry point

**Numbers recorded:**
| Model | Load time | Inference time (first run) |
|---|---|---|
| CLIP ViT-B/32 | ~4,600ms | 86.9ms |
| YOLO11n | ~200ms | 505ms (first, CUDA compile) |
| BLIP-2 OPT-2.7B | ~1,700ms (from cache) | 434ms |
| Total pipeline | — | 1,139ms |

**Decisions made:**
- YOLO11n (nano) chosen over larger variants — runs alongside CLIP and BLIP-2 on the same GPU without VRAM contention. Confidence threshold calibration deferred to Block 3D.
- BLIP-2 OPT-2.7B loaded in float16 to halve VRAM usage (~3GB vs ~6GB).
- CLIP model identifier: `openai/clip-vit-base-patch32` (HuggingFace). Note: `openai/clip-vit-b-32` returns 404 — wrong identifier.
- torchvision must be installed from the cu128 PyTorch index (not PyPI) to enable CUDA NMS in YOLO.

**Acceptance criterion:** `python scripts/run_pipeline.py assets/img.jpg` prints tags, caption, embedding shape `(512,)`, norm `1.0000`, and per-model latency. GPU active. ✅

### Block 1B — Qdrant integration and evaluation contract 🔄

**What was built:**
- `scripts/split_data.py` — one-time 4,000/1,000 data split (seed=42)
- `app/pipeline/qdrant.py` — Qdrant client wrapper (connect, create collection, upsert, search)
- `scripts/index_images.py` — batch CLIP embedding and indexing of 4,000 images
- `scripts/generate_eval_pairs.py` — GPT-4o-mini vision used to generate 200 eval queries
- `scripts/eval_recall.py` — Recall@10 evaluation script

**Numbers recorded:**
| Step | Result |
|---|---|
| Images indexed | 4,000 / 4,000 |
| Indexing throughput | 55 img/s |
| Indexing total time | 72.7s |
| Recall@10 baseline | **0.94 (94.0%)** — 188/200 hits |
| Qdrant search latency | avg 13.7ms, p95 15.0ms (10 queries, top-10 results) |

**Decisions made:**
- Qdrant chosen over FAISS (no persistence, no API) and ChromaDB (not production-grade at scale). Qdrant provides built-in persistence, metadata filtering, and a REST API.
- COCO image ID (numeric, from filename) used as Qdrant point ID — enables direct correlation with COCO annotations in Phase 3.
- Eval queries generated from `data/index/` images (not holdout). Holdout images are never indexed so their IDs can never appear in search results — querying from holdout makes Recall@10 always zero.
- GPT-4o-mini (`detail: low`) used for query generation — vision-capable, ~$0.05 for 200 images, generates specific realistic queries that manual writing would take ~3 hours.

**Methodology note:** Recall@10 of 0.94 is higher than the knowledge base's expected 0.70–0.78 because (1) queries were generated by GPT-4o-mini and are more specific than typical human queries, and (2) source images are in the index so CLIP retrieves the exact image. The 0.70–0.78 range assumes human-written queries from holdout images not in the index — a harder task.

**Acceptance criteria:**
- [x] `data/eval_pairs.json` committed with 200 query pairs
- [x] Recall@10 baseline recorded — 0.94 (GPT-4o-mini queries, index images)
- [x] Search latency under 100ms locally — p95 15.0ms ✅

### Block 1C — FastAPI backend ✅

**What was built:**
- `app/api/models.py` — Pydantic schemas: `TagResult`, `UploadResponse`, `SearchResult`, `SearchResponse`
- `app/api/routes/upload.py` — `POST /upload` endpoint: validates file type, runs YOLO + BLIP-2 + CLIP, upserts to Qdrant, returns tags + caption
- `app/api/routes/search.py` — `GET /search` endpoint: embeds query with CLIP, queries Qdrant top-K, returns results with scores
- `app/api/main.py` — FastAPI app with lifespan: loads all models once at startup, stores on `app.state`

**Numbers recorded:**
| Metric | Value |
|---|---|
| Upload pipeline time | 243.8ms (YOLO + BLIP-2 + CLIP, warm models) |
| Search response | Sub-20ms (CLIP embed + Qdrant lookup) |

**Decisions made:**
- YOLO tags are deduplicated by label — two people detected becomes one `"person"` tag. Tags are a label set for search filtering; counts are handled by the BLIP-2 caption.
- `top_k` capped at 50 to prevent runaway Qdrant queries.
- Models loaded via FastAPI lifespan (not module-level) — only loads when server starts, not on import.
- Image IDs for uploaded files derived from `abs(hash(filename)) % 2**63` — deterministic, no database needed for ID management in Phase 1.

**Acceptance criterion:** `uvicorn app.api.main:app --reload` → Swagger UI at `/docs` → `POST /upload` returns tags + caption, `GET /search` returns ranked results. ✅
